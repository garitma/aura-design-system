Aura uses [Emil Kowalski’s skills](https://github.com/emilkowalski/skills) for motion, polish, and interface craft, and [Vercel’s React best practices](https://github.com/vercel-labs/agent-skills/tree/main/skills/react-best-practices) for React and Next.js performance. They were compared with the skills already in this repo and with the team’s skill library before anything was copied. Two skills that do the same job are not both installed.

`aura init`, `aura setup`, and `aura blueprint` copy the reconciled set into `.cursor/skills/`. Docs for the runbook are the [Agent blueprint](/docs/mcp-agent-blueprint). This page is the practice: what each skill is for, when to apply it, and how to update it.

Both licenses allow copying. The files in `packages/cli/templates/cursor/skills/` are the copies the blueprint ships. They are not floating installs of `npx skills add`.

Aura foundation rules and `DESIGN.md` win when a skill disagrees: 13px spacing, accent and gray steps, fluid type, the 17px floor on editable inputs, and the animation tokens (buttons `cubic-bezier(0.4, 0, 0.6, 1)`, dialogs `cubic-bezier(0.16, 1, 0.3, 1)`, about 250ms, CSS `@theme` tokens). gdp-ts proofs win over the Vercel note `server-auth-actions`.

## What Aura ships

| Skill | Use it when |
| --- | --- |
| `emil-design-eng` | Shaping or reviewing polish, component decisions, and which motion belongs. Criteria only. It does not edit a design file. |
| `animate` | Building a web animation: whether it should exist, then tool, properties, curve, and duration. |
| `review-animations` | Reviewing motion in a diff against exact curves and durations. Explicit invoke. Default is to flag. |
| `improve-animations` | Auditing motion in a codebase and writing self-contained fix plans. It does not apply the fixes. |
| `find-animation-opportunities` | Looking for places that should animate, with exact values, and places that should not. Read-only. |
| `animation-vocabulary` | A motion effect is described vaguely and needs its name before a design or implementation decision. |
| `apple-design` | Gesture, spring, depth, type, or restraint decisions in an Apple-like way, translated for the web. |
| `prototype` | Several genuinely different versions of one UI piece, behind a picker. Explicit invoke. |
| `mobile-native` | A web app feels like a website on a phone: tap highlight, `100vh`, safe areas, overscroll, input zoom. Inputs stay at 17px. |
| `break-ui` | Stress-testing a screen with worst-case data: long names, empty lists, huge counts. |
| `ask-sonner` | A file already imports `sonner` (DataGrid still does). New toasts use the Aura toast. |
| `react-best-practices` | Writing or reviewing React or Next.js for waterfalls, bundle size, server work, and re-renders. The skill `name` is `vercel-react-best-practices`. |

The team library already had adaptations of `emil-design-eng`, `animation-vocabulary`, `apple-design`, `find-animation-opportunities`, `improve-animations`, `review-animations`, and `prototype`. Where those were short pointers at an external criteria file, the full upstream text is now in the skill, and the team’s “do not edit a design file” line stays. Where the team’s body already matched upstream (`animation-vocabulary`, `find-animation-opportunities`), that body stayed. `humanize` is a team prose skill and does not share a job with this set, so blueprint does not install it.

## Close calls

These are not installed. Say if one of them should be.

- **`write-swift`** has no equivalent, and Aura and the SGD apps do not ship Swift.
- **`animate-expo`** has no equivalent. It is React Native and Expo. Web motion is `animate`.
- **`pick-ui-library`** would tell an agent to install Sonner, recharts, Base UI, or a motion library. Aura components and the shadcn skill already cover that job. NumberFlow, Liveline, and similar picks are not in Aura; that is why this one is a close call rather than an obvious skip.
- **`ask-sonner`** is installed, but only as a guide for files that already import `sonner`. Dropping it entirely is the other defensible choice, because new toasts should not grow a second toaster.

## Install or update

From the app root:

```bash
pnpm dlx @aura-design/cli@latest blueprint
```

The same command runs at the end of `aura init` and `aura setup`. Re-running it refreshes the pinned skills when the copy in the CLI has changed, and does nothing to them when they already match. It does not create a second folder. A same-named skill under `.agents/skills/` is removed.

`--force` overwrites wiki bootstrap files. It is not required to update these skills.

The skills are not part of `@aura/skills` in the registry. Consumer projects get them from blueprint.
